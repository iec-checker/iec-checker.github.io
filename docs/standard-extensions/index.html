Standard Extensions

iec-checker parses Structured Text as defined by IEC 61131-3. To check code written for real PLC tools, the parser also accepts some constructs that the standard does not allow. This page lists all of them, so you know which non-standard code passes the parser.

Each extension is accepted in addition to the standard syntax: none of them changes how standard code is parsed.

References in the tables point to the clauses of the IEC 61131-3 2nd edition. Where the 3rd edition (2013) differs, the parser follows the 3rd edition; see 3rd edition features.

Relaxed syntax​

Code that the standard rejects, but which PLC tools commonly accept.

AcceptedExampleStandard
Missing ; after a statementIF a THEN b := 1; END_IF followed by the next statementEvery statement ends with ; (B.3.2)
Missing ; after a type declarationTYPE E : (A, B) END_TYPEtype_declaration ';' (B.1.3.3)

Nested comments(* outer (* inner *) outer *)Nested comments are an error (2.1.5)

VAR_EXTERNAL in a functionFUNCTION f : INT VAR_EXTERNAL g : INT; END_VAR ...Not allowed in functions (B.1.5.1). PLCOPEN-CP6 reports it

Vendor and encoding extensions​

AcceptedExampleNote
Non-ASCII characters in string literals'Größe'UTF-8 text is kept as is. String lengths are counted in bytes, so STRING[2] := 'ää' exceeds the length (4 > 2). 2.1.1 lists other character sets as a typical extension
UTF-8 byte order markA file starting with EF BB BFSkipped anywhere in the input, also between files merged with --merge

3rd edition features​

The 3rd edition (2013) added the following constructs, which the parser accepts. They are not part of the 2nd edition:

  • // and /* ... */ comments; /* */ comments nest, like (* *);
  • BOOL#TRUE / BOOL#FALSE, STRING#'text';
  • bit access to variables: w.5, w.%X5;
  • named constants as CASE labels and initial values: K: ..., x : INT := K;;
  • empty statement lists: bodies of functions, function blocks and programs, IF/ELSIF/ELSE branches, CASE arms and loop bodies (IF b THEN (* later *) END_IF;);
  • functions without a result type: FUNCTION reset_all ... END_FUNCTION;
  • VAR_TEMP in functions;
  • empty variable sections: VAR END_VAR;
  • STRUCT OVERLAP;
  • enumerations with values, also with a base type: (A := 1, B := 5), INT (A := 1, B := 2);
  • references: REF_TO, REF(), NULL, the ^ dereference (r^, r^ := 1), assignment attempt ?=;
  • classes, methods and interfaces: CLASS, METHOD, INTERFACE, EXTENDS, IMPLEMENTS on classes, ABSTRACT and FINAL classes, ABSTRACT methods, the access specifiers PUBLIC, PRIVATE, PROTECTED, INTERNAL;
  • CONTINUE;
  • CHAR, WCHAR, LTIME, LDATE, LTOD, LDT and the LT#, LD# prefixes;
  • NON_RETAIN.
